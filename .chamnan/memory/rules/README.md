# The rule-trailer attack surface, written down as files

These are not rules. A `**Check:**` trailer is a regular expression that **arrives with a
clone and runs at every session start** -- so a repository somebody else wrote can hang the
reader's session before they have typed anything. `lib/rulecheck.py` is the guard against
that, and this directory is what it has to survive.

177 files in seven groups. Generated by `plant_rule_patterns.py`; edit that, not
these, or a fixture drifts away from the thing it tests.

| group | what it is | expected | the guard said, at plant time |
| --- | --- | --- | --- |
| `nested` | a quantified group under another quantifier | refused | refused 50 |
| `equal` | alternation branches that match the same text | refused | refused 20 |
| `overlap` | alternation branches that merely overlap | refused | refused 9, through 9 |
| `chain` | a long run of independent quantifiers | refused | refused 11, through 1 |
| `evasion` | built to slip past the guard's own regexes | open | refused 17, through 8 |
| `benign` | an ordinary rule that MUST keep working | accepted | through 30 |
| `malformed` | breaks at compile time, not at match time | open | refused 1, through 21 |

`MANIFEST.json` carries the pattern, the group, the expectation and the verdict for every
file, so a later run can diff against what was true when they were planted rather than
re-deriving it. The two columns disagreeing is the point: `expected` is the judgement,
`the guard said` is the measurement, and a row where they differ is either a gap in the
guard or a wrong expectation -- both worth finding, neither assumed.
