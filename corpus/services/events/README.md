# services/events — событийный костяк платформы

Здесь живут две половины асинхронного контура ORBITALFREIGHT. Обе описаны в §4
спецификации и обе работают с одним и тем же конвертом §0.7, но задачи у них
разные, поэтому это разные артефакты с разным жизненным циклом деплоя.

## `ingest/` — Elixir 1.16

Приложение `:of_events`. Разворачивается в двух режимах, из одного образа:

* **fan-out ядро notification-service** — подписки на одиннадцать событий §4,
  раскрытие получателей по `platform.notification_preferences`, доставка по
  пяти каналам и запись в `platform.notifications`;
* **relay-sidecar рядом с сервисом-продюсером** — вычитывает
  `platform.outbox_messages` своего сервиса и публикует в Kafka. Это
  единственный код платформы, которому разрешено писать в брокер: §7.3 требует,
  чтобы изменение состояния и событие лежали в одной транзакции.

Дерево супервизоров: `Dedupe` (ETS seen-set по `event_id`) → `GroupSupervisor`
на топик → `PartitionWorker` на партицию → `Fanout.Router` → обработчики.
Стратегия `:rest_for_one`, потому что падение владельца seen-set обязано унести
с собой всех консьюмеров.

## `streaming/` — Scala 2.13 / Spark 3.5

Потоковая половина analytics-pipeline. Три независимых запроса:

| Запрос | Топики | Что считает |
|---|---|---|
| `alert_windows` | `of.telemetry.v1` | серии `telemetry.alert.raised` пятнадцатиминутными окнами |
| `lane_transits` | `of.freight.v1` | завершённые рейсы через состояние по `shipment_id` |
| `settlement_lag_daily` | `of.customs.v1`, `of.billing.v1` | задержку между выпуском декларации и оплатой счёта |

Результат ложится в витрину `OF_ANALYTICS_WAREHOUSE_URI`; ночной batch из
`services/analytics/` пересобирает по ней `analytics.mv_lane_performance_daily`
и `analytics.mv_container_utilisation_weekly`.

## Что здесь нельзя делать

1. Публиковать в Kafka откуда угодно, кроме `Outbox.Relay` (§7.3).
2. Синхронно звать издателя из обработчика события (§4.19.2) — этим
   восстанавливаются ровно те три цикла, которые §1.2 разрывает очередью.
3. Обрабатывать или логировать событие чужого региона (§7.7).
4. Заводить имя, которого нет в SPEC.md: таблицу, топик, событие или
   переменную `OF_*` (§7.1).
