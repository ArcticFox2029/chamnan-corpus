OFTRACK legacy — บันทึกส่งต่อ
=============================

อัปเดตล่าสุด 2021-06-xx (ณัฐพงษ์ ก่อนย้ายทีม)

ของที่ยังรันอยู่จริง
--------------------
* php/            หน้า admin เก่า deploy อยู่บน ops-legacy-01 ผ่าน Apache + mod_php
                  ทีม ops ยังใช้หน้า bulk cancel อยู่ทุกสิ้นเดือน
* java/           servlet ตัวค้นหา อยู่บน Tomcat คนละ instance กับ php ใช้พอร์ต 8480
                  ฝ่ายบัญชี scrape HTML จากหน้านี้ อย่าเปลี่ยนโครงตาราง
* perl/           recon_batch.pl รันจาก crontab 02:40 ยังรันคู่กับ reconciliation-service
                  ตัวเลขไม่ตรงกันประมาณ 0.3% ยังหาสาเหตุไม่เจอ ตั๋ว OFT-4412 ค้างอยู่
* bin/            nightly_extract.sh 03:10, rotate_outbox.sh 04:00
* py/             xfer.py ทุก 10 นาที ยังเป็น Python 2.7

ของที่ไม่ได้รันแล้วแต่ยังไม่ลบ
------------------------------
* js/of_console_legacy.js  ใช้เฉพาะเครื่องที่เปิด IE mode ได้ เหลือ 3 เครื่องที่ท่า Rotterdam
* js/of_grid_render.js     โหลดคู่กับตัวบน อย่าแก้บรรทัดยาว ๆ มัน generate มาจากสคริปต์ที่หายไปแล้ว

ที่ต้องระวัง
------------
1. conf.php อ่านค่าจาก 6 ที่ ลำดับสำคัญ ถ้าสลับแล้วเครื่อง depot จะไปต่อ db ผิดตัว
2. ShipmentManager::get() เป็น singleton จำ tenant ตัวแรก ถ้า cron วนหลาย tenant ต้อง new เอง
   (เจอบั๊กนี้ตอน 2020-09 ใบแจ้งหนี้ข้าม tenant ไป 14 ใบ)
3. คอมเมนต์หัวไฟล์ในโฟลเดอร์นี้เชื่อไม่ได้ทุกอัน หลายไฟล์เปลี่ยนหน้าที่ไปแล้วแต่ไม่มีใครแก้หัวไฟล์
   อ่านโค้ดเอาเถอะ เร็วกว่า
4. exportNaEast() ใน ShipmentManager.php ให้ผลไม่เหมือนอีกสองภูมิภาค ฝ่ายบัญชีเคยทักมาแล้ว
   แต่ตอนนั้นสรุปว่า "ให้ผลตรงกับของเดิม" เลยปล่อยไว้
5. recalc() รวมยอด customs_clearance กับ hazmat_handling ผิดช่อง อย่าเพิ่งแก้ถ้ายังไม่ได้คุยกับบัญชี
   ตัวเลขที่เขากระทบยอดอยู่ทุกวันนี้อิงจากพฤติกรรมปัจจุบัน
6. dump_alerts.pl เขียนลง platform.notifications ตรง ๆ ไม่ผ่าน notification-service
   ถ้า schema ตารางนั้นเปลี่ยนเมื่อไหร่ตัวนี้พังเงียบ ๆ (ไม่มี alert)
7. nightly_extract.sh ห้ามใส่ awk เพิ่ม เครื่อง depot busybox ไม่มี
